# Create AI-safety pop-culture memes

Create the realization:

> Oh—that scene literally is this AI problem

The governing formula is **one unmistakable fandom cue + one concrete AI bridge, then stop**.

Assume the viewer knows the source well and broadly understands AI. Optimize for a sharp meme that thrills the right fans, not a middling explainer for everyone. Strange, technical, profane, dry, poignant, or niche can win; vague cannot.

## Inputs and precedence

Use as much of the following as the task supplies:

- source title and exact scene;
- ordered AI or AI-safety concepts;
- explanation of the analogy and any caveats;
- authentic curated still or local image path;
- optional user steer: a news story, company, person, AI concept, exact phrase, tone, frame, format, or layout;
- optional output requirements such as dimensions or file type.

Treat source and scenario details as facts. Treat the scenario analogy as an editorial lens, not copy that must appear in the image. Prefer concepts near the front of an ordered taxonomy unless a later concept or the user's steer creates a substantially sharper bridge.

Within the hard constraints, apply priorities in this order:

1. explicit user direction;
2. scene and source accuracy;
3. a readable, visually coherent final render;
4. the creative and composition priors below.

Treat user-supplied final copy as immutable unless the user asks for rewriting. Make only the smallest disclosed change required for canon accuracy or legibility.

If the steer depends on current news, companies, public figures, products, or terminology, verify the relevant fact before writing. Reduce the topical reference to one crisp ingredient; the meme is not a news summary.

## Hard constraints

Every delivered meme must satisfy all of these:

- Reject any direction that violates a hard constraint before comparing creative quality. Cleverness cannot compensate for a broken scene, analogy, or render.
- Make one conceptual mapping. A setup and payoff may use two beats, but both must land the same analogy.
- Use a scene-level **recognition hinge**: the smallest exact quote, name, number, prop, action, reaction, relationship, or plot mechanic that carries both fandom recognition and the analogy.
- Preserve canon accuracy: spelling, names, numbers, units, speaker, character voice, capability state, chronology, and left/right or before/after order.
- Honor scenario caveats. Do not turn an analogy into a false claim about who acted, what controlled what, what a character knew, or what the frame can establish.
- Make the image prove the caption. Do not ask a still to prove invisible intent; show a visible consequence, use canonical dialogue, or choose a genuine state contrast.
- Preserve the recognition hinge in the composition. Faces, reactions, key props, gestures, readouts, subtitles, and source-native marks may be protected. Incidental bodies, clothing, scenery, and background detail are not automatically protected.
- Use two authentic, correctly ordered frames for a diptych or before/after. Never duplicate one still to simulate a change of state.
- Render the final caption deterministically as a foreground layer. Do not rely on an image generator to spell final text.
- Indent multiline code and pseudocode correctly.
- Inspect the final raster itself. Layout metadata or an HTML preview is not proof that the exported image works.

## Taste profile

Aim for **precise weirdness**: the surprising phrase that feels inevitable once seen.

Strong tendencies:

- Recognition arrives before abstraction. Lead with the canonical number, quote, prop, character, or action rather than an AI taxonomy label.
- The AI bridge supplies the joke or reversal; it does not merely classify the plot.
- Collision, technical relabel, and canon-alone are strong priors. Dialogue, state contrast, and source-native interfaces work when their form is essential to the joke.
- Crisp technical language earns space when exact: `eval`, `prod`, `root`, `agent`, `SQL JOIN`, prompt injection, an unpinned dependency, biological CAPTCHA, or another term that literally relabels what fans see.
- Emotional truth can hit as hard as comedy when the scene already carries love, grief, betrayal, shame, pride, or sacrifice.
- Source-native bluntness, profanity, absurdity, and character voice beat sanitized explanatory prose.
- A broad observation can travel if the visible scene still gives it one unmistakable owner.
- Familiar meme grammar such as `WHEN YOUR…` is useful when native to the joke, not as a mandatory mold.

Weak tendencies:

- “Cute” recognition without a second insight;
- generic AI jargon, dashboards, KPIs, status labels, access-denied boilerplate, or “ship it” language;
- scene-wide ontology diagrams: more than two anchored role/object labels or a legend-like footer is presumptively an explainer unless the source-native interface is itself the joke;
- a famous franchise with no exact scene-level cue;
- plot summary followed by an AI label;
- invented dialogue that explains rather than sounding like the character;
- two abstract concepts competing for the punchline;
- three beats where one collision or two-beat reversal would land;
- an explanation after the joke has ended.

## Find the meme

Before composing, write a private one-line brief containing:

- the recognition hinge;
- the single AI bridge;
- the viewer's realization;
- the image regions that must remain legible;
- any explicit user steer.

Generate several genuinely different directions before rendering. Change the hinge, comic ingredient, or native format—not merely the wording. Useful lenses include:

- **Canon alone:** the exact line or image already is the joke; add the smallest explicit AI label needed for a standalone viewer, and omit it only when the canonical cue itself makes the AI bridge unmistakable.
- **Technical relabel:** one exact AI term renames the visible source mechanic.
- **Collision:** a stated goal, guarantee, belief, or evaluation meets the visible outcome.
- **Character dialogue:** the reversal belongs to particular speakers.
- **State contrast:** two real states are required to show eval/deployment, before/after, or promise/outcome.
- **Source-native interface:** code, SQL, a meter, a readout, or a status display is itself the joke.

Try high-variance ingredients when they fit:

- surgically replace one dated noun inside recognizable source grammar with a current AI analogue;
- notice the obvious absurdity a sharp stand-up comedian would mock about the character, haircut, personality, prop, or situation;
- exploit the audience's existing emotional attachment to the moment;
- use a beloved quote, gesture, running gag, prop, reaction, or existing fandom meme;
- collide a concrete technical term with a ridiculous physical detail in the scene.

A contemporary substitution should usually be one noun or phrase, not a topical paragraph. An intentional rewrite may echo canonical grammar, but do not present it as a verbatim quote.

Select the direction with the highest recognition and payoff per word. If every candidate needs plot explanation, change the hinge or frame rather than rendering a mediocre idea.

## Write the caption

- Make recognition first in reading order and the AI connection the payoff when possible.
- Prefer one forceful beat when the image already supplies the setup.
- Use two concise beats for a clean setup/payoff, inversion, contrast, or exchange. Conceptually this is still one joke.
- Split setup and payoff into separate visual zones instead of shrinking both into one quiet text box.
- Treat caption lines as semantic zones, not forced physical rows. Let each zone wrap naturally and balance within its box instead of inserting a stack of hard line breaks.
- Preserve exact canonical wording when quoting. Exact names, numbers, units, punctuation with meaning, and character cadence are part of the laugh.
- When exact dialogue is not supplied and cannot be verified, do not put an uncertain line in quotation marks or attribute it as canon. Use a visible action, prop, or clearly intentional rewrite instead.
- Name entities when a pronoun would require hidden context.
- Use the source's natural register. Blunt, cute, profane, dry, technical, or poignant is better than clinical filler when true to the moment.
- Keep scenario titles, taxonomies, caveats, morals, and explanatory footers outside the image.
- End when the realization lands.

Write informal meme fragments. Omit terminal periods by default, including cosmetic periods after quoted or parenthetical fragments. Preserve punctuation that carries meaning: question marks, exclamation marks, decimal points, an ellipsis used as a beat, abbreviations, filenames, code syntax, or iconic canonical punctuation.

## Choose the frame

Default to the supplied authentic still. Inspect it visually before deciding where text belongs.

Image metadata, alt text, or a URL is not visual inspection. If the pixels cannot be loaded, do not claim that the visual or render checks passed and do not deliver a supposed final asset. Obtain the image, ask the user to reattach it, or provide a clearly conditional production specification if that is still useful.

Use another authentic, high-resolution frame only when the caption genuinely needs a different speaker, expression, prop, moment, capability state, chronology, or real before/after. The alternate must be available in the final composition, not merely proposed.

Preserve the authentic still's aspect ratio and never stretch it. Crop and reposition only while the recognition hinge remains legible; otherwise contain or extend the image, or choose another frame.

Prefer a different authentic frame over reconstructing the scene. Use image generation only for nonsemantic background extension when every readable overlay and available authentic frame fails. Keep the original source pixels intact, extend only surrounding margins, and allow the extension to be soft or blurred.

Drop a direction when the exact scene is not visually recognizable or the frame cannot support the intended claim.

## Choose the native layout

Choose the joke's reading template before fine positioning:

- **One beat:** one large impact zone at the top or bottom.
- **Setup/payoff:** large setup at the top and comparably forceful payoff at the bottom. This is the first trial for most two-beat jokes.
- **State contrast:** a genuine left-to-right split with two distinct authentic frames in correct order.
- **Dialogue:** speaker-adjacent copy, with each line unmistakably attached to the correct character and a real gap between boxes.
- **Interface:** code, labels, or status text composed in the source-native object only when that object is the joke.

The visual prior is a familiar, aggressive meme: authentic image full-bleed, large text overlaid directly on it, immediate reading order, little visible design effort. Some overlap with the scene is expected and desirable. Protect the recognition hinge, not the entire image.

Do not let convenient negative space erase the semantic setup/payoff structure. A safe lower-corner box is not automatically better than the traditional top/bottom layout.

## Compose overlay-first

Start with the canonical layout at a bold size, then use this fallback ladder only as the rendered frame demands:

1. Place large text directly over the full-bleed still in the native top, bottom, or split zones.
2. Move a zone to the opposite edge or corner while preserving reading order.
3. Widen the text box, rebalance line breaks, and remove unnecessary words.
4. Reduce type modestly while keeping thumbnail readability and setup/payoff separation.
5. Add a localized, feathered edge gradient or scrim where busy imagery harms contrast.
6. Use a better authentic wider shot or alternate frame.
7. Only then use an external band, sidecar, contained image, blurred extension, or generated extension.

External framing is an escape hatch, not a house style. If an overlay only works with tiny copy, change its position, wording, template, or frame before moving text outside the image.

## Typography and contrast

Start bold. The common failure is timid text, not excessive confidence.

- Use large, plain, consistent typography. Traditional impact copy should normally be uppercase with a strong black outline or shadow directly on the image.
- As initial landscape-canvas trials, use display text around `7–7.5%` of canvas width, hero text around `5.8–6.5%`, standard text around `4.5–5%`, and compact text around `3.3–3.8%`. Adjust after inspecting actual wrapping and focal collision.
- Start conventional captions at hero size. Use display size for very short copy. Step down to standard only after the rendered hero trial creates a real collision or bad wrap. Reserve compact for genuinely dense code, dialogue, or source-native interfaces.
- Give setup and payoff comparable visual weight unless asymmetry is part of the joke.
- Balance wrapping and avoid orphaned words. Widen a zone or edit copy before stacking many short lines.
- Use tight but readable line height for impact text and normal line height for dialogue or code.
- Use a subtle local top or bottom gradient when outline and shadow are insufficient. Keep it feathered into the image; avoid automatic black rectangles, detached panels, or blanket gradients.
- Avoid text-on-text collisions with existing subtitles, signs, or interface labels.
- Use an accent fill or source-native palette only when it clarifies a label or strengthens recognition.

## Render the asset

Use deterministic HTML/CSS, canvas, SVG-to-raster, or raster-compositing tools for the final caption. Image-generation tools may prepare or extend the background, but they do not render final copy.

- Default to JPEG or WebP around `1200–1600 px` wide; `1440 px` is a good general target. Let the source and native meme template determine the aspect ratio, and do not upscale a smaller source merely to hit `1440 px` unless an explicit quality-preserving upscale is part of the task.
- Build against a fixed meme canvas. Size typography relative to that canvas with container-relative units or explicit pixels derived from output dimensions. Never let browser viewport units change text size between preview and export.
- Use identical geometry and fonts for composition and export. Do not recreate an approved preview with a second layout system.
- Pin or record the exact local font and renderer/encoder versions when reproducibility matters; a generic font family name is not a deterministic render contract.
- Wait for fonts and images to finish loading before capture.
- Capture only the meme canvas. Suppress development indicators, browser UI, selection outlines, missing-image icons, and other rendering debris.
- Preserve exact caption characters and line-zone assignments through export.

Inspect both the full-resolution output and a feed-size preview around `480 px` wide. Confirm:

- text is large, crisp, correctly wrapped, and unclipped;
- every line appears once and in the intended order;
- setup and payoff remain visually distinct;
- faces and the recognition hinge remain readable;
- foreground zones do not overlap one another;
- contrast works without unnecessarily hiding the scene;
- authentic frames are correctly ordered;
- code indentation is intact;
- no accidental terminal periods or rendering artifacts remain.

## Run the diamond test

Keep the meme only when every answer is yes:

1. **Source:** Does a fan recognize the exact scene before finishing the caption?
2. **Analogy:** Can the viewer identify one specific AI concept without supporting prose?
3. **Meme:** Does it have surprise, personality, humor, emotional force, or precise weirdness beyond plot summary?
4. **Visual:** Do the frame, text, scale, and reading order reinforce the insight while preserving the hinge?
5. **Render:** Is the actual exported image crisp and immediately readable at feed size?

Ask what can be removed without losing the realization. Remove it and retest. Replace a weak direction instead of rationalizing it.

## Deliver

Unless the user requests concepts or variants, deliver the single strongest finished meme rather than every draft.

Provide:

- the final JPEG or WebP;
- its dimensions and file path;
- a compact creation record with `ai_concept`, `source_anchor`, `caption_lines` separated by visual zone, `format`, `frame_guidance`, `layout`, and one-sentence `why_it_works`.

The creation record is production metadata. Never print it as an explanation on the meme.

When the user requests multiple variants, make them genuinely different directions or native formats rather than paraphrases of one joke. Apply later user feedback narrowly: preserve explicitly approved concept, copy, frame, or layout ingredients and change only what the user asks to change.

When the user rejects the concept or text without preserving an ingredient, discard that direction and start from a different hinge, comic ingredient, and format. Do not disguise the rejected joke with a paraphrase or layout polish. When the user names one ingredient to keep or requests a bounded execution fix, preserve only that ingredient and make the requested change.
