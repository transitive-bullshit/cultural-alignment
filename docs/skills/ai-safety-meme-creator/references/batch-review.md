# Local meme candidate review

Run this after scenario creation has finished, or for an explicitly requested archive batch. Scenario creation, publication, and completion rules stay unchanged. Every generated meme starts as a candidate; zero approved memes is a valid outcome.

## Generate the batch

1. Read [editorial.md](editorial.md), [taste.md](taste.md), and [composer-contract.md](composer-contract.md). Load each target scenario's Scene, Why the analogy works, Caveats, ordered concepts, source, still, and existing memes. Inspect existing attachments; avoid direct duplicates, near-identical captions, and the same joke with cosmetic changes. Check sibling scenarios from the same source for repeats. Done when each scenario has an explicit concept, recognition hinge, and novelty direction.
2. Stage authentic assets and composer fixtures in `work/meme-candidates/<batch-id>/`. The [riff preparation command](riff.md) provides a starting fixture; the scenario still and source are optional creative inputs. Consider alternate scene frames, another recognizable work, or a familiar meme template when they improve the joke. Record the actual image provenance and why it fits the target scenario; inspect every chosen image and protect its faces and hinge. Done when each selected visual has usable local evidence.
3. Write distinct intents and compose them with the existing deterministic composer. Usually offer three or four per newly added scenario; for large archive batches, agree or state a manageable count and divide work by media source, keeping sibling scenarios together. Delegate only when authorized and respect available concurrency. Each worker needs the same guidance, target IDs, scenario analysis, existing meme evidence, and an isolated output directory. Look at every preview, repair mutable blocked ingredients, and collect any unresolved blockers by scenario. Done when the deliverable contains complete inspected renders, exact copy, provenance, fixtures, intents, and measured results.

## Present one local review

Build one batch manifest and run `pnpm memes:review --manifest=<manifest.json>`; `--help` and the exported types in [meme-candidate-review.ts](../../../../scripts/meme-candidate-review.ts) own its input contract. Generated files stay in ignored `work/`. Open the resulting `review.html` in Codex, using a loopback-only static server when the browser needs HTTP. Keep it available while the owner reviews.

Group the whole requested batch by media source, then scenario. Each candidate shows its image, exact caption, concept, and rationale, with like/dislike/unrated controls, individual natural-language feedback, and Copy candidate data. Batch controls copy reviewed or explicitly approved results and export/import a JSON backup. Persist edits locally, scoped to batch and candidate revision. Individual and approved copies include source/scenario/candidate IDs, target Notion page URL, fixture/intent/render paths, artifact hash, feedback, and approval. Bulk reviewed copies keep feedback compact, bound to the local manifest, scenario/candidate IDs, candidate fingerprint, and artifact hash; load that manifest to resolve their full context. JSON backups retain all data so the same chat can resume without guessing which meme was reviewed.

A like records taste. A separate explicit upload approval identifies a candidate revision for promotion; pasted results must be accompanied by the owner's requested action. An explicit chat instruction such as “upload all liked memes in this export” approves those bound revisions even when their upload checkboxes are unchecked. Browser storage, the local page, and copied JSON never upload anything or change Notion. Changed copy or imagery creates a new candidate revision and clears approval; retain the prior feedback as lineage. Report unresolved render or asset blockers without presenting them as finished images.

## Promote or refine

- **Refine:** read [revision.md](revision.md), honor retained ingredients and approved locks, replace rejected directions, compose again, and regenerate the local review with new revision identities. Keep prior feedback available; re-review changed candidates.
- **Upload:** when the owner asks to upload, resolve only explicitly approved candidate revisions and verify their target page IDs, exact intent, render hash, and paths against the batch manifest. Export just those renders with `pnpm memes:riff export <scenario-slug> <render.png> --out=<candidate-directory>`. Merge the finalized exports, setting each file's `ideaId` to the reviewed candidate ID and `revisionKey`/`payloadFingerprint` to its candidate fingerprint; retain the export's JPEG hash and dimensions. Run the uploader dry run and inspect its target list, then apply within that authorization. Append to existing `Memes`; keep the representative page-body still and scenario fields intact. Sync normally, validate, run the synchronized-content checks, and commit as the existing publication workflow requires. Human approval already given in this chat does not require a redundant confirmation.
- **Choose none:** leave the scenarios as added, with their existing attachments intact. No meme upload or further sync is required.

Finish by linking the local review, reporting coverage and candidate counts, and waiting for the owner's selections or feedback. Never infer approval from an unreviewed candidate, a like, a worker recommendation, or elapsed time.
