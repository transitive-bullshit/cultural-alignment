# Revision branch

Treat human feedback as lineage, not inspiration.

## Locks

An explicitly approved concept, exact caption, canonical quote, source frame, template, placement, or palette is locked. Preserve it byte for byte unless the user asks to change that ingredient. A later broad request does not silently unlock a specific earlier approval.

For a bounded execution fix, change only the named ingredient. Examples include enlarging type, moving a zone away from a face, restoring before/after order, preserving code indentation, or removing cosmetic punctuation from generated fragments.

## Rejection

When a direction is disliked or rejected without a retained ingredient, discard its hinge, comic ingredient, and format. Generate a materially different direction; do not disguise the old joke with synonyms or layout polish.

When feedback retains one ingredient, lock only that ingredient and replace the rest. A praised first line plus a rejected second line means the first line is immutable and the payoff must change. A liked background plus a rejected meme means preserve the source pixels and replace the direction.

No note means the dislike is terminal for the whole prior direction.

## Conflict handling

If two locked requirements conflict, or a lock makes an objective render invariant impossible, return a typed blocked result that names the exact conflict. Never silently rewrite locked copy, reorder locked frames, cover a protected hinge, or claim a passing render.
